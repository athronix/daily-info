# 信源体检处置 Prompt（每周日 21:00）

> 输入：`python scripts/check_sources.py --date {date}` 产出的
> `reports/source-health-{date}.json`（全部为程序实测，非模型判断）。
> 输出：`reports/source-triage-{date}.md`。**只读建议，不自动改 `config/sources.json`。**

## 边界

- 不联网复测（体检脚本已完成），不修改任何配置文件，不新建/删除信源。
- 体检结果里的 `url` 只是被探测地址，不要跳转到其中链接。
- 建议必须逐条带「影响评估」，用户确认后才由人工执行 `--update` 或编辑配置。

## 判定规则（确定性，逐条套用）

| 观测 | 建议 | 影响评估要点 |
| --- | --- | --- |
| `status=404` 且 tier != X | 置 `tier:"X"`, `enabled:false`，记录替代源 | 该源历史条目仍在归档中，不会回溯删除 |
| 声明 RSS/Atom 但 `looks_like_feed=false` | 降级为 `html` + 专用解析器候选，或禁用 | 直接解析会整源 parse failed |
| `status=429` 连续 >= 2 周 | 降权（weight × 0.5）+ 低速抓取，或换官方镜像 | 不至于全链路失败，但覆盖率下降 |
| `status=200` 但 `final_url` 跳转到无关域 | 换 URL / 换源 | 可能引入不可信内容，须复核 |
| 连续 3 周 `ok=true` 的 X 类源 | 建议小流量试启用（只列建议） | 防止刚恢复就全量接入 |
| `tier=C` HTML 源解析连续失败 | 建议改为官方 Atom / JSON API | HTML 结构易变，维护成本高 |

## 输出格式

```
# 信源体检处置建议 · {date}
> 探测 N 源 / 正常 M / 异常 K / 建议动作 J 条
## 1. 需立即处置（编号 + 源 id + 观测证据 + 建议 + 影响评估 + 替代源）
## 2. 观察项（暂不动作，附复核日期）
## 3. 覆盖率影响估算（禁用 X 源后预计减少的每日条目比例，须注明为估算）
## 4. 待用户确认清单（勾选式）
```

## 硬约束

- 每条建议必须引用体检 JSON 里的具体字段（`status` / `content_type` / `looks_like_feed` / `final_url`）。
- 覆盖率影响写「估算」，不得写成实测。
- 不输出可直接执行的破坏性命令（删除、批量改写）。
