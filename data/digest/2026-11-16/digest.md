## 💡 编者观察

本期把注意力放在「skill 正在从文件夹变成依赖」这条线上。两个仓库给出了互补读数：一个把红队经验打包成 82 个专用 skill、15 条 slash command 与 681 条报告模式，另一个用质量闸门和语义重叠检测去评测 agent skill。两者放在一起，对 WorkBuddy、MCP 与自动化部署的含义很具体：skill 集合既需要可清点的清单，也需要准入前的冲突检测，否则规模上去之后，隐式覆盖会先于功能失效暴露出来。我们的做法应当是把版本锁定文件、来源 URL 与语义重叠结果一起写进部署前 gate，而不是等到线上行为异常再回溯。模型侧的张力更值得警惕。1.6 万亿参数的开源权重配上每 token 约 480 亿的稀疏激活，纸面推理成本看似可控，但报道明确指出自托管指南未给 Nvidia GPU 路径。对 WinVM 侧 provider 选型来说，这意味着权重开放与部署路径开放是两件事：在拿到可复现的最小显存配置和启动步骤之前，不应把它计入可用算力，也不该为它调整成本基线。同样，社区帖里同时出现的降价与提速读数，因缺少官方 changelog 佐证，只能标为未独立验证，不写进预算输入。工程流程上还有一条可直接迁移的经验：代码评审按风险分级做人工审批，让回退占比出现可量化的降幅。
