## 3. 两个 Tier C 站点的逆向接入（纠错）

11-04 的结论是「纯客户端渲染、需无头浏览器、暂禁用」。**这个结论是错的**，本轮推翻：

### 3.1 智源社区 `hub.baai.ac.cn` → Tier B 匿名 JSON API

1. 首页 18KB Nuxt SSR 壳里，`__NUXT__` **内嵌了 6 条 `story_info`**（标题 / 摘要 / 原文链接 / 时间 / 标签），并非「零文章数据」；
2. 从 `/_nuxt/ab9f904.js` 提取出后端域名 `hub-api.baai.ac.cn` 与路径 `/v1/story/list`；
3. 实测 `POST https://hub-api.baai.ac.cn/api/v1/story/list` + `{"sort":"new","page":1}`
   → `200 {"code":0,"data":[{"story_info":{...}}]}`；`GET` 返回 405，所以必须 POST；
4. **无需账户、无需 cookie、无需无头浏览器**。

为此给 `fetch_sources.py` 增加 `method` / `body` / `headers` 字段支持，`common.json_api_items` 增加 `baai-hub` 分支。
实测产出 6 条当日实时资讯（如 09:20「Anthropic 未发布模型挖出 Linux 内核漏洞」），带标签与摘要。

### 3.2 `d.aigclink.ai` → Notion 匿名 API + Reader 降级

1. 首屏是 Notion SPA（`data-notion-html`），HTML 里只有壳；从 `requiredRedirectMetadata` 拿到真实 `pageId=fe1ce99b-…`；
2. 匿名 `POST /api/v3/loadPageChunk` → 200，拿到 `collection_view_page`「AI日报」及 6 个视图；
3. 匿名 `POST /api/v3/queryCollection`（collection `bf0ecb26-…` + view `8f252a54-…`）→ 200 / 592KB / 367 blocks，
   **能拿到完整结构化行**；
4. 但实测 `query.sort` 对匿名请求不生效：三种排序（created_time / 日期属性 / last_edited_time）都只返回**最早的 20 行（2024 年起）**，取不到当日增量；
5. 因此主链路改用 `https://r.jina.ai/https://d.aigclink.ai/` 的 Markdown 渲染结果：最新优先，每条含
   **标题 + YYYY/MM/DD + 标签 + 摘要 + 站内原文链接**，`common.parse_html_items` 的 `aigc-link` 分支解析。

实测产出 30 条（最新批次 2026-11-03）。**诚实边界**：r.jina.ai 是第三方渲染代理、有速率限制，
故该源标 Tier C、失败整源降级不阻断日报；`queryCollection` 的结构化路径保留在本文档，
等日后找到有效排序参数或有权限会话时可切为主源，不在源表里放「启用但跑不出东西」的摆设。

## 4. 需要账户的源：能力边界、已实现机制与你要做的事

### 4.1 为什么我没有「自动注册」

用户 60 站清单里真正需要账户的站点，注册流程都包含**邮箱/手机验证、OAuth 授权同意、付费或 KYC**
（Crunchbase、PitchBook、IT 桔子、WSJ / The Information / Stratechery 付费墙、X、Meta Ads Library 等），
服务条款通常也禁止自动化注册；当前运行环境没有可收验证邮件的邮箱，也没有可持久化的浏览器会话。
因此**本轮没有代替任何站点注册，也不会伪造「已注册」状态**。

但「需要账户」不等于「拿不到数据」：所有能匿名获取的等价入口本轮已全部接入（见 §4.5）。

### 4.2 已落地：`.env` → 进程环境 → `${VAR}` 占位（密钥不落仓库）

项目纪律是「不存储任何 API Key / token 在仓库」（`docs/03`）。链路分三环：

1. **`common.load_dotenv()`**（2026-11-05 新增）：按 `PERSONAL_DAILY_INFO_DOTENV` →
   `~/.workbuddy/.env` → `项目根/.env` 的优先级读**第一个存在的文件**，把 `KEY=VALUE` 注入
   `os.environ`（已有值不覆盖、支持 `export` 前缀与引号包裹）。
   背景实证：WorkBuddy **不会**把 `~/.workbuddy/.env` 自动注入子进程（注入前
   `GITHUB_TOKEN/USER/EMAIL` 在 `os.environ` 全为 MISSING），所以采集链必须自己加载。
   全程不打印、不落盘、只返回注入键数。
2. **`common.resolve_credentials()`**：源配置写 `"Authorization": "Bearer ${GITHUB_TOKEN}"`，
   运行时取值；变量未设置 → 整个 header 丢弃、自动回退匿名（不存在半配置状态）；
   URL / body 占位替换为空串。
3. **`common.redact_credentials()`**：会进 `data/raw` / `reports` 的字段（`final_url`、HTTP 异常
   文本等）里若出现已注入的凭据值，统一还原为 `${VAR}` 占位。落盘记录本身用带占位的原始 URL
   与缓存键，**天然脱敏**。

发布前凭据正则扫描（V3 闸门）继续作为最后一道防线；`.gitignore` 已挡 `.env` 兜底路径。

## 6. 本轮新增的三个坑（已写入 pitfalls P22–P24）

- **P22**：把「首屏 HTML 无内容」直接等同于「无法程序化接入」——忽略了 SSR 内联数据与匿名后端 API；
- **P23**：`200 + Content-Type: application/xml` 也可能是**未声明 Content-Encoding 的 gzip 体**，
  `parse_feed` 会直接失败；已加 `common.decode_payload` 按 gzip 魔数兜底；
- **P24**：同域多源叠加会迅速耗尽限流（Reddit 3 个子版 → 全 429），且反爬挑战页会伪装成 200 HTML；
  体检报告必须留证据，不能把「体检通过」当成「永久可用」。

## 8. 维护约定（新增）

1. 新源一律走 `candidates.json` → `probe_candidates.py` → `register_sources.py` → `check_sources.py` → `fetch_sources.py --only <id>`，
   **禁止手工把未体检 URL 直接写进 `sources.json` 并启用**；
2. POST 型源必须写清 `method` / `body` / `headers`；GET 返回 405 不是失效，别误判；
3. 密钥只走 `${ENV_VAR}`，任何把明文写进配置/产物的改动都会被 V3 凭据闸门整体拒发；
4. Tier C 源允许整源降级，但必须在 `note` 写明降级原因与替代路径，不许留「启用但恒为空」的摆设；
5. 每季度复查 `candidates.json` 里被拒的 49 个（403 站点常换反爬策略），复查仍按三重体检标准。
