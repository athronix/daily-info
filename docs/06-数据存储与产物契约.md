# 06 · 数据存储与产物契约

> **v2 更新**：§3.2 的 `digest.json` 示例是精简版。v2 每条 item 额外含七要素字段，
> 顶层额外含 `lead / watch_signals / reference_summary / stats.seven_element_ratio`，
> `quality` 增加 `number_whitelist / entity_whitelist / content_spec_version`。
> 完整字段见 `assets/skills/daily-info/references/architecture.md` §5.1 与 `config/content-spec.json`。

## 1. 存储选型

| 层 | 格式 | 位置 | 理由 |
| --- | --- | --- | --- |
| 配置 | JSON | `config/*.json` | 人可读、可 diff、配置驱动 |
| 原始快照 | JSON（每源一份） | `data/raw/<date>/` | 可重放、便于排障；不存大段原始 HTML（可选 `--save-payload`） |
| 归一数据 | JSONL | `data/normalized/<date>/items.jsonl` | 一行一条，流式处理，易 grep |
| 去重状态 | SQLite | `data/state/seen.db` | 单表 + 主键，跨天去重与 novelty 衰减 |
| 运行日志 | JSONL | `data/state/run-log.jsonl` | 追加式，记录每步统计与健康度 |
| 推送记录 | JSONL | `data/state/push-log.jsonl` | 分发幂等，防同日重复投递 |
| 事实源 | JSON | `data/digest/<date>/digest.json` | **唯一事实源**，所有对外通道投影自它 |
| 人读产物 | Markdown | `digest.md` / `brief.md` | Git 版本化、可离线读、资料库沉淀 |
| 服务产物 | JSON / Atom | `public/` | 静态托管，无后端 |

**不引入**：数据库服务、缓存服务、向量库、对象存储、SSR 框架。
依据参考仓库的实证：纯文件 + Git 能支撑 9 个月、每日多流的长期运行。

## 2. 目录契约与留存策略

| 路径 | 内容 | 留存 |
| --- | --- | --- |
| `config/` | sources / taxonomy / scoring / subscriptions | 永久（Git） |
| `data/raw/<date>/` | 每源快照 + `_summary.json` | **30 天** |
| `data/normalized/<date>/` | items.jsonl + `_summary.json` | **180 天** |
| `data/candidate/<date>/` | clusters.json / prompt-input.json / boundary-review.json | 180 天 |
| `data/digest/<date>/` | ai-review.json / digest.json / digest.md / brief.md | **永久** |
| `data/digest/week-<ISO>.json` | 周复盘打包输入 | 永久 |
| `data/state/` | seen.db / http-cache.json / run-log / push-log | 永久 |
| `public/data/` | index.json / latest.json / `<date>.json` / feeds.json | 永久 |
| `public/*.atom` / `feed.json` | 订阅投影 | 每次重建（幂等） |
| `reports/` | 体检 / 核验 / 周报 / 月报 / 留存报告 | 永久 |

**清理铁律**（`scripts/retention.py`）：
默认 `--dry-run` 只出报告；`--apply` 需用户明确确认、每批 ≤10 个目录、逐批校验、异常即止；
只处理 `data/raw/` 与 `data/normalized/` 下严格 `YYYY-MM-DD` 的过期目录，
**永不触碰** `digest/` / `candidate/` / `state/` / `public/` / `config/` / `reports/`。

> 对照 docs-feed：`max_entries=100` 硬截断、旧文档静默消失、无归档、无快照，
> 且 3.9 MB 单文件每日全量重写提交进 Git，仓库线性膨胀。
> 本方案让 feed 只做「最近 100 条的投影视图」，历史全量留在按日期分目录的 digest 里。

## 3. 核心 schema

### 3.1 Item（`data/normalized/<date>/items.jsonl`）
见 `assets/skills/daily-info/references/architecture.md` §3，字段包括
`id / source_* / title / url / canonical_url / published_at / fetched_at / lang /
summary_raw / category / tags / matched_rules / metrics / repeat_count / tokens /
cluster_id / score / ai`。

### 3.2 digest.json（唯一事实源）
```json
{
  "date": "YYYY-MM-DD",
  "headline": "...", "headline_short": "...", "generated_at": "...Z",
  "themes": [{"title":"...","why":"...","cluster_ids":["..."],"verified_by":2}],
  "sections": [{"key":"...","label":"...","items":[{
      "id":"...","title":"...","url":"...","source":"...","published_at":"...",
      "score":78.2,"category":"...","cluster_id":"...","summary":"...","why_matters":"..."}]}],
  "editor_note": "...", "brief": "...",
  "stats": {"sources_ok":26,"sources_total":29,"total_items":430,
            "clusters":118,"selected":40,"published_items":38},
  "quality": {"ai_status":"ok|degraded","missing_data_marker":"暂无可靠数据",
              "warnings":[],"id_whitelist":true,"url_whitelist":true,
              "credential_scan":"clean"},
  "demo": false
}
```

**不可变约束**：`sections[].items[].id` 与 `url` 必须能在 `clusters.json` 中找到；
`make_digest.py` 白名单过滤，AI 自带 url 一律忽略，异常记入 `quality.warnings`。

### 3.3 站点切片
- `index.json`：`site` 元信息 + `dates[]`（日期 / headline / demo / stats / section_count /
  item_count / ai_status）+ `feeds[]`（id / label / url）；
- `latest.json`：最新一天完整 digest；
- `<date>.json`：与 `digest.json` 同内容，静态站按日期切换；
- `feeds.json`：5 个 profile 的 URL / filter / 条目数。

## 4. 单一时间口径

| 字段 | 口径 |
| --- | --- |
| `published_at` | UTC ISO8601，`Z` 结尾 |
| `generated_at` / `fetched_at` | UTC ISO8601，`Z` 结尾 |
| 业务日期 `date` | Asia/Shanghai 自然日（`today_str()`，UTC+8） |
| 时间窗 | 过去 30 小时 + 未来 30 分钟容差 |
| `entry id` 中的日期 | 业务日期，稳定不变 |

**文件名日期、文内日期只作展示，绝不参与排序或去重判定。**
对照：blogpost 从文件名解析日期（36 篇非日期文件回退 git log 或写死 `"2026-02"`），
docs-feed 一律用 git 提交历史；同一内容库上下游两套口径导致日期不一致。

## 5. 幂等与原子写入

```
write_json(path, obj)
  → 序列化（ensure_ascii=False, indent=2）
  → 与现有文件字符串比较；相同 → 返回 False（不落盘）
  → 不同 → 写 path.tmp → Path.replace(path)（原子替换）

write_bytes_idempotent(path, bytes)
  → 字节比较 → 相同不写 → 否则 .tmp → replace
```

- 所有排序带确定性 tie-break（`-score, cluster_id` / `-updated, repository, path`）；
- `xml_text()` 剔除 XML 1.0 非法控制字符，避免序列化失败；
- `ET.indent` 固定缩进，`xml:lang` 固定值；
- 内容不变 → 不写文件 → 不触发重新发布 / 不重复推送；
- `verify_digest.py` V5 通过「二次构建 + 全产物 sha256 比对」实证字节一致。

来源：docs-feed 的 `generate_feed.py:204-210`（字节比较 + `.tmp→replace`）与
`publish_feed.py:34`（`git diff --cached --quiet` 决定不提交），本方案去掉了它的
`reset --hard`（会在开发者工作区丢改动，只能用于 CI 临时工作区）。

## 6. 发布前安全闸门

| 位置 | 检查 | 命中后 |
| --- | --- | --- |
| `make_digest.py` | AI 产物（headline / editor_note / brief / sections）凭据正则 | `SystemExit`，拒绝合成 |
| `build_feeds.py` | 全部待发布条目序列化文本凭据正则 | 返回码 2，**保留旧 feed** |
| `verify_digest.py` V3 | digest.md / brief.md / 所有 atom / json 凭据 + 危险 HTML | violations > 0，禁止分发 |

凭据特征：`API_KEY/SECRET/ACCESS_TOKEN/PASSWORD = xxx`、`ghp_/gho_/ghu_/ghs_/ghr_`、
`github_pat_`、`sk-`、`-----BEGIN ... PRIVATE KEY-----`、`credential.helper`。
危险 HTML：`<script` / `onerror=` / `javascript:` / `<iframe`。

**这条闸门直接针对参考仓库实证风险**：`blogpost/finnhub-integration-complete.md`
明文含 `FINNHUB_API_KEY` 与 GitHub token 的 `credential.helper` 写法，
且不在 docs-feed 的排除清单里；当前 atom 中 0 命中属「尚未泄漏」，
一旦元文档被刷新就会全文进入公开订阅源。`bleach.clean` 只做标签白名单，拦不住正文密钥。

补充原则：**不要只靠黑名单 exclude**，优先用 include 白名单
（如「仅允许日期命名文章」）+ 凭据扫描双保险。

## 7. Git 版本化与分发

- `digest.md` / `digest.json` / `config/` / `docs/` / `scripts/` / `public/index.html` 入 Git；
- `data/raw/`、`data/normalized/`、`data/candidate/` 建议加入 `.gitignore`（可重建、体积大）；
- `data/state/seen.db` 属于状态，跨机迁移时随工作区复制；
- 参考仓库用「一日一提交」+ 仓库即发布载体很有效，本方案保留；
  但**生成代码也在仓库里**，避免「只有成品、没有工厂」。

## 8. 备份与恢复

| 场景 | 做法 |
| --- | --- |
| 某天采集失败 | `python scripts/run_daily.py --date <日期>` 补刊；按日期目录互不覆盖 |
| 站点数据损坏 | `python scripts/build_site.py` 从 digest 全量重建 |
| 订阅源损坏 | `python scripts/build_feeds.py` 从 digest 全量重建 |
| seen.db 丢失 | 重新初始化空表；novelty 会短暂重置，不影响内容完整性 |
| 429 / 网络抖动 | 保留已落盘中间产物，从失败步骤续跑，不清空重来 |
| 历史事实源丢失 | digest 永久保留 + Git 历史 + 资料库沉淀，三处冗余 |

## 9. 误报风险与数据边界

- `verify_digest.py` 的 `violations=0` 只说明**结构、白名单、安全、幂等**通过，
  **不证明新闻事实为真**；外部事实一律标注「未独立验证」；
- `stats` 里的计数来自本系统自身统计，未经第三方核对；
- `--offline-demo` 产出的所有条目均为本地样例，报告会带 `demo:true` / 站点显示「演示数据」徽标，
  **不得当作真实日报对外分发**；
- 降级日报 `ai_status=degraded` 只列规则层标题与原文摘要，不含研判；
- 覆盖率、压缩比等估算值在文档中均标注「估算」，实测值以 `_summary.json` / `digest.stats` 为准。
