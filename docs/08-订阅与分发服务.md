# 08 · 信息获取与订阅服务设计

> **v2 更新**：Atom `content[type=html]` 与 JSON Feed 现在渲染完整七要素
> （事实锚点 / 关键数字 / 相关方 / 影响 / 下一步 / 证据状态 / 外置原文链接），
> 不再只有一句摘要。分流 profile 当日为空属正常视图状态（主入口仍必须非空）。

> 配置：`config/subscriptions.json`；实现：`scripts/build_feeds.py`；
> 站点入口：`public/index.html` 页脚；核验：`verify_digest.py` V3 / V4 / V5。

## 1. 六个出口（全部投影自同一事实源）

| # | 通道 | 产物 | 状态 | 更新规则 |
| --- | --- | --- | --- | --- |
| 1 | 静态站 | `public/index.html` + `public/data/*.json` | 启用 | 每次日报后重建，内容不变不重写 |
| 2 | Atom 全文订阅 | `public/*.atom`（5 个 profile） | 启用 | 全量确定性重建，稳定 entry id |
| 3 | JSON Feed | `public/feed.json` | 启用 | 供程序/脚本消费，带扩展字段 |
| 4 | 邮件日报 | `assets/templates/email.html` + agent-mail | 启用 | 07:15，附 `feed.atom` |
| 5 | 企业微信机器人 | `brief.md`（≤1500 字） | 默认关闭 | 定时任务「消息推送到企业微信」 |
| 6 | 资料库沉淀 | `我的文档/每日信息/{YYYY}/{MM}/` | 启用 | MD 存叙事 / CSV 存索引 / HTML 做呈现 |

**唯一事实源原则**：六个通道都从 `data/digest/<date>/digest.json` 投影，
不各自另写一份内容，避免参考仓库里「README 索引与实际文章数不一致」的漂移。

## 2. Atom 1.0 全文订阅

### 2.1 五个 profile

| profile | 过滤表达式 | 产物 | 用途 |
| --- | --- | --- | --- |
| all | `score >= 45` | `all.atom`（同时 `feed.atom`） | 默认入口，全量日报 |
| high-signal | `score >= 70` | `high-signal.atom` | 只看高信噪 |
| tech | `category in taxonomy.groups.tech` | `tech.atom` | 技术与工程 5 类 |
| invest | `category in [market-invest, industry-capital]` | `invest.atom` | 市场与产业 |
| docs | `category == docs-changelog` | `docs.atom` | **文档变更雷达** |

`build_feeds.match_filter()` 支持 4 类表达式（数值阈值、等值、in 列表、in 分组），
新增 profile 只需在配置里加一行。

> 对照 docs-feed：单一 feed、3 个来源级 category、无按主题订阅。
> 本方案把订阅维度做成配置驱动的视图。

### 2.2 feed 级与 entry 级字段

```
feed:  id=tag:daily-info.local,2026:<profile> · title · subtitle
       link[rel=self] · link[rel=alternate] · updated=最新条目 generated_at
       author(name)
entry: id=tag:daily-info.local,{date}:{cluster_id}        ← 稳定不变
       title="[板块] 标题" · link[rel=alternate] · published · updated
       category{term,label} · summary[type=text] · content[type=html] 全文
```

- **稳定 entry id**：编辑/重跑不改变 id，阅读器不会因「每天都跑」误报更新；
  内容变化才更新 `updated`。这来自 docs-feed 的 git-history 时间语义，
  但本方案用 `date + cluster_id` 而不是文档 URL，避免改名/移动造成重复收录。
- **全文 content**：每条自建固定标签 HTML（摘要、为什么值得看、来源/时间/分类、原文链接），
  所有外部文本 `html.escape`，无 script / onerror / javascript: / iframe。
- `max_entries=100`，但**历史不丢失**——feed 只是视图，全部历史在 `data/digest/` 永久保留。
- 生成后 `ET.fromstring()` 自校验 XML 合法性。

### 2.3 订阅地址（重要坑）

- 用**站点静态地址**：`<在线域名>/feed.atom` 或 `<在线域名>/all.atom`；
- **绝不要用 GitHub 仓库页自动生成的 `https://github.com/<user>/<repo>/releases.atom`** ——
  那是 GitHub 的 Release 订阅，与同名仓库文件完全不同（docs-feed README 第 7 行专门警告）；
- 如需本地测试，用 `http://localhost:8765/feed.atom`（不是 `127.0.0.1`，见 `07`）；
- **MIME 注意**：2026-11-04 实测 `python -m http.server` 对 `.atom` 返回
  `application/octet-stream`。上线时给 `.atom` 配 `application/atom+xml`，
  或在订阅教程里提示手动添加 URL（详见 `pitfalls.md` P17）。

## 3. JSON Feed 1.1（程序消费）

`public/feed.json` 字段：`version / title / home_page_url / feed_url / description / language / items[]`。
每个 item 除标准字段外带 `_daily_info` 扩展：

```json
"_daily_info": {"score": 78.2, "source": "TLDR AI",
                "cluster_id": "...", "ai_status": "ok"}
```

用途：给后续脚本做时间序列分析、自定义筛选、导入其它工具；
比纯 Markdown（参考仓库的做法）机器可读得多。

## 4. 邮件日报（agent-mail）

| 项 | 值 |
| --- | --- |
| 连接器 | `agent-mail`（当前会话可用） |
| 收件人 | 本账户 Agent Mail 地址（用 `GetMe` 获取，不硬编码） |
| 发送时间 | 07:15（主链路核验通过后） |
| 主题 | `[每日信息] {date} · {headline_short}` |
| 正文 | **`scripts/render_email.py` 自动渲染** `assets/templates/email.html` → `data/digest/<date>/email.html`，≤24000 字符（P1 实测 23 条完整七要素 = 18387 字符，见 P29） |
| 附件 | `public/feed.atom` + `data/digest/<date>/digest.md` |
| 幂等 | `push_daily.py` 先查 `data/state/push-log.jsonl`，同日同通道已准备则跳过 |
| 收件人 | `agent-mail GetMe` 动态获取，配置里只留 `SELF_AGENT_MAIL_ADDRESS` 策略占位 |

邮件模板包含 headline、stats、主线、分类条目、编者观察、站点链接与免责声明，
配色与站点一致，纯内联样式（邮件客户端兼容性）。渲染产物含 `email-subject.txt` 与
`email-meta.json`（附件清单、字数、凭据扫描结果、待授权状态）。
**脚本只生成本地 payload，不发送**；站点未上线时不输出 `daily-info.local` 占位死链。

## 5. 企业微信推送

- 开关：定时任务编辑窗口 →「消息推送到企业微信」；
- **仅支持 WebSocket 长连接方式绑定的机器人**，URL 回调方式不支持；
  绑定后须先在企业微信里给该机器人发过一条消息，否则收不到推送；
- 内容：`brief.md`（≤1500 字）短简报 + 站点链接，不推全文；
- 默认 `enabled:false`，未开启不影响其它通道。

## 6. 资料库沉淀

目录：`我的文档/每日信息/{YYYY}/{MM}/`

| 文件 | 类型 | 用途 |
| --- | --- | --- |
| `digest.md` | 文档 | 人读叙事，可被知识库检索 |
| `index.html` | 页面 | 呈现与在线分享 |
| `items-<date>.csv` | 表格 | **P1 已实现**：当日条目索引（id / 日期 / 板块 / 标题 / 分类 / 来源 / 分数 / 发布时间 / 数字 / 实体 / URL / 佐证 URL），UTF-8 BOM |
| `no-number-<date>.csv` | 表格 | **P1 新增**：入选簇中「原文无实质数字」的条目诊断，用于补上游摘要而非放宽阈值（见 P28） |
| `index-<date>.html` | 页面 | **P1 已实现**：自包含离线快照（内联 CSS + 数据），不依赖站点 `data/` 相对路径 |
| `weekly-*.md` / `monthly-*.md` | 文档 | 周报 / 月报归档（P2） |

「发布为网站」会同时把页面存入资料库；MD 存叙事、CSV 存索引、HTML 做呈现，
符合资料库对不同类型资产的分工。原则：只放终态产物，不放 raw/normalized/candidate 中间层。
`export_library.py` 生成的是**本地 staging**（`data/library/<YYYY>/<MM>/`），
附 `_manifest-<date>.json`（文件清单 + sha256 + 口径标记）；
上传动作需用户授权后由 Agent 按 manifest 执行。

## 7. 幂等、去重与留存

| 机制 | 实现 |
| --- | --- |
| 稳定 entry id | `tag:daily-info.local,{date}:{cluster_id}` |
| 内容不变不写盘 | `write_bytes_idempotent` 字节比较 + `.tmp→replace` |
| 分发去重 | `push-log.jsonl` 按日期记录，dedupe window 7 天 |
| 全量确定性重建 | 每次从全部 digest 重建，排序带 tie-break，保证字节可复现 |
| 发布闸门 | V3 凭据/危险 HTML 扫描、V4 Atom 合法性、V5 幂等 |
| 留存 | raw 30 天 / normalized 180 天 / digest 永久 / feed ≤100 条 / 站点归档永久 |

## 8. 发布前安全闸门（关键）

```
digest.json → build_feeds.py
   ├ 凭据正则扫描（全部待发布条目）
   │    命中 → 返回 2，拒绝生成，保留旧产物
   ├ HTML 自建固定标签 + 全量 escape
   └ Atom / JSON Feed 写入
        ↓
verify_digest.py V3 二次扫描 + V4 解析 + V5 幂等
        ↓ 0 violations
分发（站点 / 邮件 / 企微 / 资料库）
```

这直接针对参考仓库的实证风险：上游明文密钥可能经全文 Atom 二次扩散到公开 Raw URL，
而 `bleach.clean` 只做标签白名单，不扫正文。详见 `01` §7.4 与 `06` §6。

## 9. 与参考仓库对照

| 参考仓库 | 订阅能力 | 本方案补齐 |
| --- | --- | --- |
| daily-rss | 无自产 feed；文中给的 RSS 是上游 Karpathy 源 | 5 个自产 Atom + JSON Feed + 站点 |
| daily-investor | 无分发代码/配置，靠 GitHub Watch 与外部 publisher | 邮件 / 企微 / 资料库 / 站点，全部有显式配置 |
| blogpost | GitHub 仓库 + README 索引（手工） | 确定性生成索引 + 多通道分发 |
| docs-feed | 单一 Raw Atom，100 条硬截断，无历史/无告警 | 多 profile + 历史永久保留 + 核验闸门 + 健康报告 |

## 10. P1 分发脚本链（2026-11-05 落地）

P0 只有配置与模板；P1 把「准备到只差授权」这段工程补齐为 4 支确定性脚本：

```
verify_digest.py  (0 violations)
      ↓
check_release.py  站点端到端 18 项（IPv6 ::1 + 禁用代理，实发 HTTP）
      ↓
push_daily.py --apply
      ├ 闸门：报告日期匹配 / violations=0 / 凭据扫描干净
      ├ export_library.py  → data/library/<YYYY>/<MM>/ 6 个文件 + manifest
      ├ render_email.py    → data/digest/<date>/email.{html,meta.json,subject.txt}
      ├ data/state/push-log.jsonl（日期+通道幂等）
      └ data/state/pending-dispatch-<date>.json（待授权动作清单）
      ↓
Agent 在用户明确授权后，按清单调用外部工具
```

| 脚本 | 职责 | 是否对外 |
| --- | --- | --- |
| `export_library.py` | 沉淀包 + `items.csv` + `no-number.csv` + 离线快照 + manifest | 否 |
| `render_email.py` | 邮件正文/主题/元数据自动渲染，凭据扫描，长度闸门 | 否 |
| `push_daily.py` | 核验闸门、幂等、通道计划、待授权清单；默认 dry-run | 否 |
| `check_release.py` | 首屏 / 日期切换 / 搜索 / 5 个 Atom / JSON Feed 端到端 | 否 |

**边界**：4 支脚本都不调用 agent-mail、企微、资料库或站点发布工具。
`pending-dispatch-*.json` 逐条写明 channel / tool / payload / status，
外部动作一律由 Agent 在用户明确授权后执行（见 `pitfalls.md` P30）。

**幂等实证**：`--apply` 连跑两次，第二次 `export_library` / `render_email` 均 `changed=0`，
`push-log` 新增 0 条；`pending-dispatch` 用 `digest.generated_at` 而非实时时间戳，字节稳定。

**实测（2026-11-05）**：核验 35/35、站点 18/18、沉淀包 6 文件（23 行 items + 13 行诊断）、
邮件 18387 字 / 省略板块 0 / 2 个附件、待授权动作 6 条（3 待授权、2 随站点发布、1 关闭）。

## 11. 订阅地址上线到 GitHub Pages（2026-11-06 已上线）

订阅源需要一个**长期稳定**的公开地址，因此优先用项目站点
`https://<owner>.github.io/<repo>/feed.atom`（5 个 profile 的 Atom + JSON Feed 同理），
而非随时可变的临时预览链接。本地准备链路：

```
public/ 唯一投影
  → prepare_pages.py --base-url <真实地址> [--apply]
  → pages-dist/（绝对地址替换 + .nojekyll + manifest sha256，字节幂等）
  → 用户授权后复制 assets/deploy/github-pages.yml 到 .github/workflows/ 并触发
```

`prepare_pages.py` 与上述 4 支分发脚本同属「只做本地准备」边界：不联网、不 push、不发布；
默认 dry-run，`--apply` 仅写被 `.gitignore` 排除的 `pages-dist/`。
子路径适配、稳定 ID、feed 级 link 校验、平台限制与上线后复核清单见 `docs/16`。
**2026-11-06 已上线**：`https://athronix.github.io/daily-info/`，线上 15/15 URL 返回 200，
6 个 `.atom` 实测 `application/atom+xml`（P17 风险解除），占位 URL 0 命中、稳定 ID 59 个保留。
本地子路径预演 14/14（`reports/pages-subpath-check-2026-11-06.md`）、二次 `--apply` `changed=0`；
线上验收与偏离项见 `reports/pages-live-check-2026-11-06.md`。
workflow 仍只保留手动触发，站点更新需用户手动 dispatch。
