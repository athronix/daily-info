## 3. 推荐清单（90 站）逐类判定

清单 10 个分类里，对本系统（匿名程序化采集）真正可操作的只有约 1/3；其余分三种情况：

| 情况 | 代表站点 | 处置 |
| --- | --- | --- |
| 有官方 feed/API，已接入 | OpenAI News、DeepMind、Ben's Bites、Google Trends、HN、Google News、Product Hunt、TechCrunch、MIT TR、WIRED、Farnam Street、Aeon | 启用（见 §2） |
| 无 feed 或反爬拒绝（403/404/SSL） | Trend Hunter 403、Crunchbase 403、Indie Hackers 404、Starter Story 404、TAAI 403、Toolify 403、AlternativeTo 403、BetaList 404、Stratechery 403（付费墙）、HBR 404、The Atlantic 403、Exploding Topics 404、Import AI SSL 握手失败 | Tier X 留证据，勿反复重试 |
| 本质是「人看的」界面/工具，不适合机器采集 | X Explore、TikTok Creative Center、YouTube Charts、Quora、Pinterest Trends、AnswerThePublic、AlsoAsked、Glimpse、Meta Ads Library、Google Ads Transparency、Behance/Dribbble/Awwwards/ShotDeck/FilmSupply、Vimeo Staff Picks、Similarweb、World Bank/OECD（数据站，非资讯流）、G2/Capterra/Zapier 目录 | 不接入；作为**人工浏览**与**周报选题灵感**入口保留在清单原文（`docs/references/`） |

清单里被验证「换个用法才有效」的三条经验：
1. **Medium** → 不订首页，订具体作者/机构 feed（`medium.com/feed/@OpenAI`）；
2. **Google News** → 用 `rss/search?q=<关键词>+when:2d` 把「搜索」变成「订阅」，一个模式可派生 N 个主题源；
3. **Reddit** → `/r/popular.rss` 被 429，但垂直子版（LocalLLaMA/artificial）可用——垂直社区比聚合入口质量更高、限流更松。

## 4. BAAI hub 与 AIGC Link 的接入结论（**2026-11-05 已纠错，本节原结论作废**）

> ⚠️ 本节 11-04 写的「纯客户端渲染、需无头浏览器、Tier C 禁用」是**错误结论**。
> 用户 11-05 明确要求「不论 Tier B or C 都要接进来」，重新逆向后两个站点都已启用并真实产出条目。
> 完整过程见 `docs/14-高质量数据源扩充与账户源指引.md` §3，根因见 `pitfalls.md` P22。

| 站点 | 11-04 的错误判断 | 11-05 实测纠正 |
| --- | --- | --- |
| `hub.baai.ac.cn` | 「首页零文章数据，`/api/*` 全 404」 | 首页 `__NUXT__` **内嵌 6 条 `story_info`**；从 `/_nuxt/ab9f904.js` 提取出 `hub-api.baai.ac.cn`，匿名 **POST** `/api/v1/story/list` 返回 `code:0 + data[]`；GET 才 405。现为 Tier B `enabled:true`，实测出 6 条当日实时资讯 |
| `d.aigclink.ai` | 「Notion 发布页，只能人工浏览」 | 匿名 `POST /api/v3/loadPageChunk` + `queryCollection` 均 200（592KB / 367 blocks）；但 `query.sort` 对匿名请求不生效、只返回最早行，故主链路用 `r.jina.ai` 的 Markdown 渲染结果（最新优先，含标题/日期/标签/摘要/原文链接）。现为 Tier C `enabled:true`，实测出 30 条 |

**教训**：判定「不可接入」前必须做三步逆向（SSR 内联数据 → JS chunk 里的 API host/path → GET/POST 两种实测），
不能只看首页 HTML 和盲猜 `/api/*`。同时「能拿数据」不等于「能拿增量」，Notion 的排序限制已如实登记。

## 5. 当日真实链路验证（新源接入后首次全量运行）

```
采集 67/68 源成功（唯一失败 reddit-artificial 429，属预期限流）
→ 原始 5,350 条 → 30h 窗口归一 804 条 → 799 簇 → 入选 40 簇
→ AI 研判 35 条 / 10 板块 / 6 主题 / 5 待验证信号
→ 七要素达标 35/35 = 100%，warnings=0
→ 订阅 all=35 / high-signal=22 / tech=20 / invest=10 / docs=0（当日无 docs 类高分条目，视图允许为空）
→ 核验 31/31 通过，violations=0；V5 幂等 changed=0
```

过程中白名单闸门**真实拦截了 3 类错误**（这正是它存在的意义）：
- `"70 亿"` 写成数字 70，但原文是 `$7 Billion` → 溯源断言失败，改为 `7`；
- 实体 `"Google DeepMind"` 原文实际写 `"Google Antigravity"` → 被丢弃并告警；
- **id 张冠李戴**：把 Boehringer 条目挂到了印度兵役的 cluster id 上 →
  实体校验连带暴露（该 id 原文里找不到 Boehringer）。已修正为正确 id `5dc01a743cffc18a`。

**诚实边界**：白名单能验「值存在于原文」，验不了「语义匹配」——上表的 id 错配是我人工核对才发现的，
`evidence-audit.md` 的 claim 级审计才是对应防线；真实日报的外部事实仍统一标注「未独立验证」。

## 6. 维护约定

- 新源必须先过 `check_sources.py` 实测 + `fetch_sources.py --only <id>` 解析验证，再启用；
- `when:2d`、`{since7d}` 这类滚动窗口参数保证「只拉增量」，避免旧内容反复进候选；
- Reddit/Bloomberg 等限流源保持 `min_interval_sec` 与并发 8 不变，连续 2 周 429 就降权；
- 清单原文存于 `docs/references/`，作为季度性复查与人工浏览入口。
