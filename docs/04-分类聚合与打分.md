# 04 · 分类聚合与打分

> 配置：`config/taxonomy.json`（分类/标签/聚类）、`config/scoring.json`（权重/阈值/配额）。
> 实现：`normalize.classify()`、`dedupe_cluster.py`。
> **这一段完全确定性、零 LLM 参与**，是整套系统可复现、可审计的基础。

## 1. 三段式分类（可解释，必须记录依据）

```
① category_hint（信源先验）
   每个源在 sources.json 里带一个 hint，如 huggingface → ai-models、
   github releases → docs-changelog、cnbc → market-invest。
        ↓ +0.25 加分（不是硬指定）
② rule_hit（关键词 / 实体规则）
   对 title + summary[:400] 做中英文关键词命中，逐类累计 hits，
   记录 matched_rules（如 "ai-models:3"）供审计。
        ↓
③ ai_adjudicate（仅对冲突或低置信条目）
   V1 默认不调用模型；只在开启增强模式时，对分类冲突/边界对做判定，
   结果仍须落回可枚举的 category key。
```

`taxonomy.principle` 原文：「分类结果必须可解释，记录 matched_rules」。
规则命中数裁剪到 ≤5，避免长文本刷分；未命中任何规则时回退 `hint`，再回退 `community`。

## 2. 归一化与去重键

`normalize.py` 做的四件事：

1. **时间窗**：只保留 `published_at` 在最近 30 小时（`window_hours`）内的条目；
   未来偏斜容忍 30 分钟；无时间的条目保留但新鲜度给 0.45 兜底分。
2. **canonical_url**：去 utm_* / fbclid / gclid / ref / spm / mc_* 等追踪参数、
   scheme/host 小写、去尾斜杠。`item_id = sha1(canonical_url)[:16]`。
3. **跨天去重**：SQLite `seen(item_key PK, first_seen, title, source_id, repeat_count)`，
   重复出现次数用于 novelty 衰减；同批次内按 `item_id` 去重。
4. **tokenize**：中文字符 bigram + 英文 `[a-z0-9+#.-]*` token，供聚类用；
   每条最多存 120 个 token，控制体积。

## 3. 聚类（去重聚合，替代「罗列」）

`dedupe_cluster.py` 用**并查集 + token Jaccard**：

```
for i < j:
  同源且标题完全相同 → 跳过（已在 normalize 层去重）
  s = |tokens_i ∩ tokens_j| / |tokens_i ∪ tokens_j|
  s >= 0.62  → union(i, j)                 # 确定同事件
  0.45 <= s < 0.62 → 记入 boundary_pairs  # 只记录，默认不调 AI
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `similarity_threshold` | 0.62 | 确定性合并阈值 |
| `ai_boundary_low` | 0.45 | 边界区下界 |
| `max_cluster_size` | 8 | 喂给 AI 时每簇最多 8 条 |
| `time_window_hours` | 30 | 与采集窗口一致 |
| 复杂度 | O(n²) | 每日几百条足够；>5000 条/日换 MinHash LSH（代码已标注位置） |

簇级加成：**独立信源数**越多加分越高（`0.04/额外源`，上限 0.2），
因为同一事件被多家独立报道是强信号——这对应 daily-rss「6-8 个核心主题、同主题跨源合并」
的编辑思路，但把它变成可计算、可审计的规则。

`clusters.json` 保存完整簇（含 tokens、score 明细、boundary hints）供审计；
`prompt-input.json` 是**唯一喂给 AI 的输入**，每字段截断并带 UNTRUSTED DATA 声明。

### 可选的边界判定（默认关闭）
`assets/prompts/theme-adjudicate.md` 定义了对 `0.45 ≤ s < 0.62` 边界对做判定的规则
（同实体+同动作 / 时间差 <48h / 转载关系，`confidence < 0.7` 一律不合并）。
开启后写 `boundary-review.json`，由 `dedupe_cluster.py --apply-boundary` 确定性重算，
**同一输入必得同一输出**，不会引入不可复现性。

## 4. 六维打分（`config/scoring.json`）

```
score = 100 × Σ(weight_i × component_i)，各分量裁剪到 [0,1]
```

| 分量 | 权重 | 公式 | 设计意图 |
| --- | --- | --- | --- |
| source_quality | 0.25 | `min(1, source.weight / 1.2)` | 权威源优先；失效源不进入打分 |
| freshness | 0.20 | `exp(-ln2 × age_h / 18)` | 18 小时半衰期；无时间取 0.45 |
| engagement | 0.15 | `max(log1p(hn_points)/log1p(500), log1p(comments)/log1p(300), log1p(stars)/log1p(5000))`；无指标用 `source_quality × 0.5` | 社区热度，对数压缩防刷榜 |
| relevance | 0.20 | `min(1, 0.35 + hits×0.08 + user_focus_bonus(0.15))` | 与分类/个人关注面相关 |
| novelty | 0.12 | `1 / (1 + repeat_count - 1)` | 跨天重复衰减 |
| coverage | 0.08 | 常量 0.6（簇级另加多源加成） | 预留给多源互证 |

簇分 = `簇内最高分 + 100 × min(0.2, 0.04 × (独立信源数 - 1))`，上限 100。

**为什么不用 LLM 打分**：参考仓库的排序全凭「编者判断」，无法解释、无法回归测试、
每天成本随条目数线性增长。确定性打分可以写单测、可以调权重、可以复盘「为什么这条没入选」。

## 5. 选择策略

| 参数 | 值 |
| --- | --- |
| `daily_total` | 40 簇 |
| `min_score` | 45 |
| `must_include_top_n` | 5（前 5 名无视分数与配额强制入选） |
| `per_category_quota` | 来自 `taxonomy.categories[].quota_per_day` |
| `tie_breaker` | cluster_score desc → 独立信源数 desc → published_at desc → id asc |
| `core_theme_count` | 8（交给 AI 归纳的核心主题数） |

流程：簇按分数降序 → 逐簇判断「分类配额是否用尽」→ 未用尽则入选 → 达到 40 停止。
**前 5 名强制入选**防止某天整体分数偏低导致日报空洞。
参考仓库实测压缩比约 4.5:1（430 → 96），本方案目标约 8–12:1（300–500 → 40），
换取更高信噪比；这是可配置的（`daily_total`）。

## 6. 降级与边界

| 情况 | 行为 |
| --- | --- |
| 某分类无候选 | 该板块直接省略，不写「今日暂无」 |
| 所有簇分数 < 45 | 仍输出前 5 名，避免空报 |
| 聚类后零簇 | `make_digest.py --fallback` 生成最小降级日报 |
| 可用信源 < 70% | `headline` 加 `[降级]`，`ai_status=degraded`，不生成编者观察 |
| 边界对很多 | 只记录数量到 `run-log.jsonl`，不自动调用模型（成本与可复现性优先） |

## 7. 可审计性

- 每条 Item 保留 `matched_rules`、`tokens`、`score_detail`、`cluster_id`、`repeat_count`；
- `clusters.json` 保留全部簇与 `boundary_pairs` 数量；
- `run-log.jsonl` 记录每步统计（raw → kept / dropped_old / dropped_dup / new_to_seen，
  cluster → total_clusters / selected / boundary_pairs）；
- `digest.stats` 把 `sources_ok / sources_total / total_items / clusters / selected / published_items`
  写进产物（借鉴 daily-rss「今日数据概览」的健康度自述）。

## 8. 与参考仓库对照

| 参考做法 | 本方案 |
| --- | --- |
| daily-rss：LLM 自行去重，压缩比 4.5:1，算法不可见 | 并查集 + Jaccard，阈值/权重全部配置化，可单测 |
| daily-rss：GitHub/HN 按外部热度值排序 | 热度作为 6 维之一，对数压缩并与新鲜度/相关性/新颖度平衡 |
| blogpost：文件名关键词分类 | 内容关键词 + 信源先验 + 可枚举分类 + 配额 |
| daily-investor：RSI/均线/利差等金融指标很丰富，但无结构化字段 | 本方案保留 `metrics` 扩展位；若接入行情，可加领域分量而不改架构 |
| docs-feed：只有 3 个来源级 category | 10 个主题分类 + 3 组 + 标签 + 5 个订阅 profile |
