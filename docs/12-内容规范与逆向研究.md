# 12 · 三仓库每日产出的内容规范、逆向推理与本项目采纳

> 本研究回答四个问题：**内容分类是什么、内容规范是什么、展示格式是什么、内容来源是什么**，
> 并在此基础上做**逆向推理与猜测**，最终把结论落进本项目的内容处理链路，
> 使日报产出「实在、具体、有效、丰富」的内容，而不是一堆标题和链接。
>
> 数据来自可复现脚本 `scripts/analyze_corpus.py`，产物 `reports/corpus-analysis.{json,md}`；
> 另精读代表性产物全文：`daily-rss/2026/11/2026-11-04.md`（331 行）、
> `daily-investor/observations/daily-report-2026-11-03.md`（388 行）、
> `blogpost/2026-11-04-agent-desktop-accessibility-tree-computer-use.md`。
>
> **证据等级**：`[A]` 产物文本/统计直证；`[B]` 产物正文的自述；`[C]` 逆向推理/猜测（明确标注，可验证）。

## 2. 内容分类（四问之一）

### 2.1 daily-rss：固定板块 = 事实上的分类体系（[A]）

高频板块（文件占比）：编者观察 95.7%、开源社区动态 89.8%、投融资快报 86.3%、
开发者工具更新 71.9%、核心主题聚合 71.1%、今日活动预告 62.9%、论文精选 61.3%、
LLM 动态速递 58.2%、今日数据概览 49.2%、行业深度 41.4%、Newsletter 精选 22.7%。

分类是**双层**的：
- 一级：11 个固定板块（内容形态/来源类型混合，如「投融资」「论文」「Newsletter」）；
- 二级：`🔥 核心主题` 下 6–8 个 `### 一、二、…` 主题（**按事件/议题聚合，不是按来源**），
  每主题 3–5 条、跨源合并、附多条原文链接。例如 2026-11-04 的七个主题：
  「Anthropic 的 170 亿美元：增长曲线与亏损曲线同框」「钱还在往里冲，但开始换跑道」
  「Agent 安全事故：从模型被骗到工具链被投毒」「Agent 进企业卡在上下文和权限」
  「开源权重：把前沿塞进你已有的硬件」「编码 Agent 的工作台之争」「版权、监管与社会反弹」。

**要点**：主题名是**判断句/张力句**，不是名词标签。这是「内容实在」的第一层。

### 2.2 daily-investor：章节编号 = 隐式 schema（[A]）

`observations/` 高频章节（约 90/137 篇稳定复现）：0. 今日一句话总结、1. 大盘表现总览、
2. 盘中走势复盘、3. 宏观环境、4. 板块表现、5. 主题与风格表现、6. 市场宽度与参与度、
7. 财报日历与财报解读、8. 机构观点与资金流、9. 重点个股新闻与异动、10. 板块轮动判断、
11. 重点关注股观察、12. 明日交易计划/观察清单、13. 风险提示、14. 最终结论、
15. 行业/技术趋势独立分析、16. 数据基建启发。

`ideas/` 高频板块：今日核心洞察 99.1%、潜在需求分析 98.2%、新产品创意 96.0%、
优先级排序 69.5%、明日预告 68.2%、验证计划（下周执行）66.8%、附录：数据来源链接 47.1%。

**要点**：`ideas/` 的分类天然是「洞察 → 需求 → 创意 → 优先级 → 验证计划」，
即**从信息到可执行动作**的漏斗，而不是资讯罗列。

### 2.3 blogpost：文件名关键词分类 + 文章内部中文编号章节（[A]）

- 仓库级分类由 `scripts/update_readme.py` 按文件名关键词硬编码：AI技术 259 / 记忆系统 26 /
  数据库 3 / 访谈翻译 1 / 其他 39（合计 328 条索引 vs 333 篇实际，口径有偏差）。
- 文章内部分类靠 `## 一、… / 二、…`（79.6% 采用），高频固定尾节：总结与展望、参考资料、
  参考文献、结论、结语、参考链接、关键数据一览。
- 另有按**内容形态**的分类：深度拆解、译文/访谈（带「原文作者/原文链接/翻译整理」头块）、
  系列文章（「第 47 篇」「上一篇/下一篇」）、推广物料、调研报告。

## 3. 内容规范（四问之二）

### 3.1 一条内容的「最小完整单元」（[A]，三仓库高度一致）

```
**<加粗判断句：发生了什么 + 具体数字/实体>** + <1-3 句解读/为什么重要>
→ <原文链接 1..N>
```

真实例子（daily-rss 2026-11-04:21-22）：
> **Anthropic 更新招股书，Q3 营收 170 亿美元**。相比去年同期增长超过 11 倍，这个速度在 enterprise software 历史上没有先例。但同一份文件里，亏损也在扩大，风险因素多达 88 项、93 页。
> → https://siliconangle.com/2026/11/02/...

**五个必备成分**：① 主体（谁）；② 动作（做了什么）；③ **可核验数字**（170 亿 / 11 倍 / 88 项 / 93 页）；
④ 判断或张力（「但同一份文件里…」）；⑤ 原文链接。
本项目此前每条只有「标题 + 一句 why_matters」，明显缺 ③④⑤ 的强度。

### 3.2 daily-rss 的显式规格（[B]，README 18-45 行 = prompt 契约）
6–8 核心主题（每主题 2–3 条，同主题合并）、GitHub Trending Top 8、HN Top 5、
LLM 动态 10–15 条、投融资 3–5 条、工具更新 3–5 条、行业深度 ≥3 篇、论文 2–3 篇、
今日活动预告、今日数据概览、编者观察 500–600 字、全文 5000–7000 字、
**所有条目必须带原文链接**、全中文精编、免责声明。

实测 2026-11-04 满足：7 个核心主题 / Trending Top 8 / HN Top 5 / LLM 16 条 /
融资 6 条 / 工具 6 条 / 深度 4 篇 / 论文 3+2 篇 / 活动 3 条 / 数据概览 7 项 / 编者观察 4 段。

### 3.3 daily-investor 的证据纪律（[A]，最值得抄的一套）
- **字段级不编造**：「凡未取到可靠数值的字段均明确标注"暂无可靠数据"，不做估算填充」（头部声明）；
  全库 **53.3%** 的观察日报真的出现了该标记。
- **推断显式标注**：「年内降息次数预期已压缩至 0-1 次（此为依据利率与商品价格的推断，非 FedWatch 官方数值）」。
- **多源恒等式核对**：`SPY×10≈SPX`、`QQQ×41≈NDX`、`IWM×10≈RUT`；单源值事后弃用并修订。
- **数值带单位/时区/口径**：`10Y 4.95% +6bp`、`SOX 10,600.40 +2.63%（跌破 200 日线 10,807）`、
  `收 7,568.92（日内区间 74% 分位）`。
- **可执行且可证伪**：「SPX 7,600 为第一压力」「SOX 能否收复 10,807」「RSP 转正 + 涨跌家数转正才算广度确认」
  ——每条观察都给了**判定阈值**，不是「持续关注」。
- **个人化章节**：16.1「数据基建启发（数据库/容量规划视角）」把行情落到本职，
  给出「embedding 版本作为一等公民管理」「append-only 事件表 + 列存物化视图」等具体工程判断。

### 3.4 blogpost 的文章模板（[A]）
```
# 标题（判断式，常带冒号）
> 数据化导语：12,669 颗星、一个月 2.2 万次 npm 下载、v1.1.0 在 11 月 3 日发布…
> 它的答案是：能，只要你愿意把「屏幕」换成「可访问性树」。
---
## 一、<判断式章节名>        ← 79.6% 采用
   1. **加粗小标题**。解释 + 具体数字 + 后果
   表格 / 代码块 / ASCII 架构图   ← 89.5% 表格、76.3% 代码围栏
## 二、…（通常 6–10 章）
## 参考资料 / 参考文献
---
*本文由 … 自动生成 / 翻译整理于 …*
```
译文类额外有「原文作者 / 原文链接 / 翻译整理 / 日期」头块与「📡 原文来源 / 🔄 翻译整理于」尾块。
**导语必须带可核验数字**，这是「具体」的最直接体现。

## 4. 展示格式（四问之三）

| 维度 | daily-rss | daily-investor | blogpost |
| --- | --- | --- | --- |
| 标题层级 | H1 + 引用块主线 + `##` emoji 板块 + `### 一、` 主题 | H1 + `> 数据日期/来源` 声明 + `## N.` 编号章节 + `### N.M` | H1 + `>` 导语 + `## 一、` + `###` |
| 分隔 | `---` 100% | 91.2% | 97.0% |
| 数据呈现 | 有序列表 + 「今日数据概览」项目符号 | **等宽代码块里的 ASCII 表格**（92.7% 文件有表格行） | Markdown 表格（89.5%）+ 代码围栏（76.3%） |
| 链接 | **11 月起 `→ https://` 独立成行**（94/篇） | 极少外链（0.4 URL/篇），靠「数据来源」声明 | `[标题](url)`（约 5.2 URL/篇） |
| 强调 | `**判断句**` 66 处/篇 | `**结论句**` 75 处/篇 | `**判断句**` 56 处/篇 |
| 结尾 | 编者观察（245/256）+ 页脚署名/时间/信源数 | 最终结论 + 风险矩阵 + 免责声明 | 参考资料 + 生成声明 |
| 特色 | 「今日速览」6 条置顶、数据概览写 pipeline 健康度 | 8 维风险表、12 只优先观察股、5 个可证伪信号 | 架构图、系列互链、译文字段块 |

**格式演进的证据**：daily-rss 板块名在 9 个月内至少变化 4 次（「今日数据概览」/「今日数据」并存），
H1 采用率 81.2%（早期以 `>` 开头无 H1）；链接写法 11 月突变；`### 一、` 中文编号只在 6 篇出现。
→ 纯 Markdown 自由文本没有 schema，改版成本低但**机器不可读**，这正是本项目要用 JSON Schema 锁死的原因。

## 5. 内容来源（四问之四）

### 5.1 域名分布（[A]）
| 语料 | URL 总数 | 唯一域名 | Top 域名 |
| --- | ---: | ---: | --- |
| daily-rss | 16,430 | 1,159 | github 1,988 / techcrunch 1,177 / huggingface 1,115 / arxiv 1,083 / infoq 818 / aibusiness 733 / HN 595 / tldr 576 / siliconangle 542 / marktechpost 491 |
| ideas | 1,776 | 194 | github 479 / huggingface 357 / arxiv 348 / HN 157 / technologyreview 117 / reuters 13 / openai 13 / anthropic 13 |
| blogpost | 1,716 | 393 | 以 GitHub / HF / arXiv / 官方博客 / X 为主，另有大量自引用 `github.com/kejun/blogpost/blob/main/...` |
| observations | 54 | 21 | cnbc 15 / techmeme 9 / finance.yahoo 5 / news.google 2 / fred 2 / cmegroup 2 |

### 5.2 三类「来源模式」
1. **daily-rss：订阅源（27）+ 顺链核查**。产物引用了大量**不在订阅清单**的站点
   （siliconangle、marktechpost、simonwillison.net、x.com、nytimes、bloomberg…），
   说明生成端会沿 feed 条目点进原文、再引用二级来源做交叉印证。
2. **daily-investor observations：几乎不外链**（0.4 URL/篇），靠头部「数据来源」声明 +
   行情 API 数值 + 多源恒等式自证。这是「数据型内容」与「资讯型内容」的根本差异。
3. **blogpost：来源可追溯 + 内部互链**。104 篇日期文章有「参考资料/原文来源」块，
   系列文章互链形成 300+ 篇的知识图谱；翻译类必带原文链接。

### 5.3 [C] 逆向推理：生成端一定做了「跨源顺链印证」
**依据**：27 个订阅源 → 1,159 个域名、16,430 条链接；且 2026-11-04 单个主题
「Anthropic 的 170 亿美元」就同时在正文引用了 siliconangle、techcrunch（2 条）、arstechnica、
siliconangle 评论文章共 4 个域名 5 条链接，还主动引入「Ben Thompson 式的追问」「反向指标 Fujifilm 磁带产能」。
**推测**：prompt 里含有「同主题合并、多源交叉验证、寻找反向证据」的指令，
且生成端具备网页抓取/搜索能力（不只是解析 feed）。
**可验证方式**：找一期日报，把所有引用域名与 README 的 27 源做差集；差集远大于 0 即成立。

## 6. 逆向推理与猜测（逐条标注等级）

### 6.1 关于生成端 prompt 与编排
| # | 推测 | 等级 | 依据 / 验证 |
| --- | --- | --- | --- |
| R1 | daily-rss 的 README 板块规格就是 prompt 主体，且是**条数硬约束**（Top 8 / Top 5 / 10-15 条 / 500-600 字） | [B]+[C] | 产物 9 个月稳定复现这些条数；README 明写；可直接对照任意一期核验 |

| R7 | 投资日报的「可执行阈值」是刻意设计，不是模型自由发挥 | [C] | 每期都出现「突破 X 才算 Y」「收复 Z 才确认」，且同一阈值跨期复用 |

| R10 | 三类语料共享同一套「加粗判断句 + 列表 + 原文链接 + 免责声明」的元规范 | [A] | 采用率见 §1，四列几乎全 100% |

### 6.2 关于「什么才算好内容」的逆向结论（本项目的设计依据）
把三仓库的共性抽出来，「实在、具体、有效、丰富」可以拆成可量化指标：

| 目标 | 可量化指标 | 参考基准（实测） |
| --- | --- | --- |
| **实在** | 每条必须有事实锚点（主体+动作）、至少 1 条原文链接；无独立证据处显式标注 | daily-rss 100% 带链接；investor 53.3% 用「暂无可靠数据」 |
| **具体** | 每条含可核验数字/版本/日期/单位；含数字的行占比 | daily-rss 41.2%、investor 48.7% |

### 明确不采纳
| 不采纳 | 理由 |
| --- | --- |
| daily-rss 5000–7000 字超长日报 | 个人每日阅读成本过高；本项目目标 40 条结构化条目 + 400-600 字观察，靠「密度」不靠「篇幅」 |

| 纯自由文本 Markdown 当唯一产物 | 机器不可读、模板易漂移；本项目以 `digest.json` 为事实源，MD 只是投影 |
| 顺链抓取不可信站点 | 本项目不绕过登录/反爬，链接只作引用，不抓正文做事实断言 |

## 8. 误报风险

1. 语料统计基于**本地浅克隆快照**（各仓库 1 次提交），反映 2026-02 ~ 11 的产物分布，
   不代表上游全部历史；月度演进结论以本地 256 篇为样本。
2. `[C]` 级推测**无法从仓库内代码证实**——三个内容仓库没有生成代码，
   只能从产物一致性与自述反推；本文逐条给出可验证方式，不等于已验证。
3. 「含数字的行占比」是粗略代理指标（数字可能是日期、编号、版本号），
   不能直接等同于「信息具体」；需结合人工精读（本文 §3 已给真实摘录）。
4. 采纳清单里的达标率（V8）验的是**字段齐备**，不验事实真伪；
   外部事实仍标注「未独立验证」，与 `evidence-audit.md` 的 `UNVERIFIED` 状态一致。
5. 参考仓库的明文密钥风险、时间口径漂移等问题见 `docs/01` 与 `pitfalls.md`，
   本研究只针对**内容层**，不重复结论。
