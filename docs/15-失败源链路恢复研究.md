# 15 · 失败源链路恢复研究（数据追溯与链路扩展）

> 触发：归档表（`docs/references/data-source.md`）中 78 个源检测未通过。
> 用户判断正确——其中大多数**内容真实存在，只是没有官方 RSS**。
> 本轮对这些源做进一步数据追溯，换链路把高质量源挖回来。

## 1. 方法论：三路链路恢复探测

新脚本 `scripts/probe_recover.py`，对每个失败源按序并测三条替代链路，
「HTTP 200 + 响应体是 feed + 解析器能出条目」三重校验通过才算恢复：

| 链路 | 原理 | 适用 |
| --- | --- | --- |
| A. Google News `site:` / 关键词 RSS 查询 | `news.google.com/rss/search?q=site:域名 OR site:域名 …`，通用兜底路由；支持 OR 多域合并、中英文 locale、关键词细化 | 任何被 Google 收录的内容站 |
| B. RSSHub 公共镜像路由 | 主站 `rsshub.app` 实测 403，镜像 `rsshub.rssforever.com` 可用；按 RSSHub 官方路由表映射（/meta/ai/blog、/36kr/newsflashes 等） | 有 RSSHub 路由的站（输出**原文直链**，质量最高） |
| C. HTML 列表页启发式 | 直连博客列表页抠「带日期的同域文章链接」 | 边缘站点（本轮命中率低，仅备用） |

结果：**78 个失败源中 69 个恢复成功（88%）**，证据见
`reports/recover-probe-2026-11-05.{json,md}`。

## 3. 关键根因与工程修正

1. **ai.meta.com/blog/rss/ 确实不存在**——Google AI 答复与本轮实测一致（404）。
   正确姿势不是硬找 feed，而是换生成链路：RSSHub 路由 `/meta/ai/blog`（原文直链）
   或 gnews `site:` 查询。已按前者登记。
2. **`min_interval_sec` 配置声明了但从未实现**：30+ 个 gnews 源同打
   `news.google.com`，无节流必触发整域 429（Reddit 三子版翻车同因）。
   `fetch_sources.py` 新增 `throttle_host()`：同主机请求按 `min_interval_sec`
   串行排队、不同主机照常并发。实测 38 源一轮采集无 gnews 限流。
3. **RSSHub 主站 403 ≠ RSSHub 不可用**：公共镜像 `rssforever.com` 可用；
   镜像属第三方共享设施有速率限制 → 全部标 Tier B/C 语义，失败整源降级不阻断日报。
4. **Folo（app.folo.is）**：页面与 API 均为登录态私有实例数据（SPA 壳 200 但零内容、
   无匿名端点），不能作为程序化信源；其价值在人工阅读器场景，不登记。

## 6. 追加轮次 B：Folo 订阅池作为基线信源（kind=cli）

用户指出 Folo 有官方 Agent 入口。调研确认两条等价链路：
- **官方 skill**（`https://api.folo.is/skill.md`）：`npx --yes folocli@latest`，
  稳定 JSON 信封 `{ok,data,error}`，`timeline --limit 100 --cursor` 游标翻页；
- **社区 folo-mcp**（hyoban 起源、1939869736luosi 扩展 12 工具）：同一底层 API +
  session token。本项目选 **CLI 直连**——零 MCP 配置、复用 load_dotenv 凭据约定、
  输出契约即官方承诺，链路更短。

接入设计（区别于普通抓取源）：
- **定位=基线层**：Folo 池每条都是用户人工订阅的，信噪比最高；权重 1.2（全注册表最高），
  同题竞争时优先采信 Folo 版，自动抓取源做增量发现；
- **只读纪律**：只 `timeline`，不 `mark-read`/不改订阅/不写任何外部状态；
- **实现**：新脚本 `scripts/fetch_folo.py`（CLI 翻页 + 宽容字段解析 + 真实 payload 落盘
  供首登校准）；`sources.json` 登记 `kind=cli` 源；`fetch_sources.py`/`check_sources.py`
  对 cli 型分别跳过 HTTP 抓取/改读最近产物探活；`run_daily.py` 在 fetch 后调用（失败软降级）；
- **Windows 坑**：`npx` 是 .cmd 垫片，Python subprocess 直接 exec 报 WinError 2 →
  首元素换 `npx.cmd`；
- **认证**：`~/.workbuddy/.env` 加 `FOLO_TOKEN=<session token>`，或跑
  `npx --yes folocli@latest login` 浏览器授权（token 7–30 天过期需续）。
  当前状态=待登录，归档表如实标「✅ 在用·待授权 / 待登录」，不伪造可用性。
